# Badcase 归因口径（判定方法）

判定方法：**金标标注 vs 实际召回客观匹配（覆盖率计算）+ 原文回溯核验**。

覆盖率由脚本客观计算（金标段落字符 bigram 在召回文本中的覆盖率），
得出 ✅ 命中 / ⚠️ 部分命中 / ❌ 未召回 三档结论；归因结论在其基础上结合
模型回答与各维度评分判定。

## 归因类别

- **A = 检索召回问题**：金标信息在知识库中真实存在，但未被召回或召回文本被截断——信息在 KB 里，召回环节丢失
- **B = 大模型定位问题**：信息已在召回上下文中（在场），但模型未正确使用——召回缺陷前提下的次责
- **C = 知识库无答案**：金标信息在知识库中不存在，模型无法作答

## 组合与书写

- 纯 A：`A 召回问题（纯）`
- 主次并存：`A主+B次`（召回缺陷为主因，模型未识别/错用为次因）
- 偶发：`B 大模型定位问题（纯）`（金标已召回但模型答错）
- 口径分歧：附加注明（如"附评测口径分歧"），当另一评测模型未判 badcase 时使用

## 归因分析写作要求

1. 先给主因（召回？定位？库无答案？），再给次因
2. 引用具体证据：金标段落原文、召回段落内容、模型回答中对应的表述
3. 提到覆盖率数值与分段命中情况；说明"信息在场未捕捉"与"信息缺失"的区别
4. 150-250 字，直截了当，像人工评审批注

## 原文核验写作要求

- 核对金标句在原文中的实际位置（段落/页码），与召回段的位置作对比
- 结论三态：`✅ 已核实`（金标在原文中且召回确实缺失/错位）/ `⚠️ 部分核实` /
  `⚠️ 标注问题`（金标绑定错误、标注串行等，需人工复核）
- 无原文材料时留空，不写推测性结论
